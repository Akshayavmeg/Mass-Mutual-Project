# Dashboard and Reporting

# 30. Dashboard and Reporting

## 1. Introduction

The **Dashboard and Reporting** module provides a centralized interface for monitoring cheque-processing activities, OCR results, validation outcomes, fraud-detection results, manual review cases, and final decisions.

The dashboard converts the system's processing data into **clear visual indicators, charts, tables, and reports** so that Operators, Reviewers, Auditors, and Administrators can quickly understand the current state of cheque processing.

The dashboard will use the data generated by the project's own processing pipeline and **mock banking/sample cheque data** during the prototype stage.

---

# 2. Objectives

The Dashboard and Reporting module aims to:

1. Provide a centralized view of cheque-processing activity.
2. Display the number of cheques processed.
3. Show Approve, Review, and Reject decisions.
4. Display fraud-related statistics.
5. Monitor OCR extraction performance.
6. Track validation failures.
7. Identify pending manual-review cases.
8. Display processing time and system performance.
9. Provide searchable cheque-processing records.
10. Provide role-based dashboards.
11. Generate operational and audit reports.
12. Support data-driven analysis of fraud patterns.
13. Maintain traceability between dashboard information and audit records.

---

# 3. Dashboard Users

Different users require different information.

| User Role          | Dashboard Purpose                                                 |
| ------------------ | ----------------------------------------------------------------- |
| **Administrator**  | Overall system health, users, processing statistics, fraud trends |
| **Operator**       | Uploaded cheques, processing status, OCR and validation results   |
| **Reviewer**       | Pending review cases, risk scores, fraud indicators               |
| **Auditor**        | Audit events, decisions, user activity, historical reports        |
| **System Service** | Provides processing data to the dashboard                         |

The dashboard must follow the permissions defined in **User Roles and Access**.

# 30. Reporting Accuracy

Dashboard numbers must be calculated consistently from the database.

For example:

```text
Total Processed
=
APPROVED + REVIEW + REJECTED
```

subject to the system's processing-status definitions.

Similarly:

```text
Manual Review Rate
=
(Number of Review Cases / Total Processed) × 100
```

and:

```text
Approval Rate
=
(Number of Approved Cheques / Total Processed) × 100
```

The dashboard should clearly distinguish between **illustrative/demo metrics** and actual measured project results.

# 39. Summary

The **Dashboard and Reporting** module acts as the monitoring and analysis layer of the Mass-Mutual cheque-processing system. It brings together information from **OCR, validation, fraud detection, risk scoring, decision processing, manual review, and audit logging**.

The dashboard will allow different users to understand the system's current status, identify suspicious cheques, monitor manual-review workload, evaluate OCR and fraud-detection performance, and generate operational and audit reports.

Most importantly, the dashboard will eventually use **our own generated mock banking data and sample cheque dataset**, so the reported statistics, fraud trends, OCR accuracy, processing time, and decision distributions will be based on actual experiments performed by our project rather than fabricated results.
